# R2-05.5 — Balanced Price Range (BPR)

- **Project:** ICT-Kronos · **Phase:** Phase 2 — ICT Engine · **Issue type:** Story
- **Story points:** 3 · **Labels:** `ict`, `bpr`, `composite`, `leakage`
- **Depends on:** R2-05 (FVG) · **Blocks:** —
- **Concept map:** [R2-05x-CONCEPT-MAP.md](../../docs/ict/R2-05x-CONCEPT-MAP.md) §5.5

## Objective

Implement the Balanced Price Range as the **geometric intersection of two
opposite-polarity FVGs**. `BprDetector` consumes `FvgDetector` output and never
rediscovers a gap.

## Dependencies

```
bullish FVG  ┐
             ├─► strictly positive price overlap ─► BPR
bearish FVG  ┘
```

## Exact semantics

**Inputs.** Exactly two confirmed FVGs of **opposite** polarity, on the same symbol and
timeframe. Same-polarity overlap is not a BPR.

**Zone = the intersection, not the union.** Per the source: *"Mark the area where both
fair value gaps intersect. That intersection is the Balanced Price Range."*

```
zone_top    = min(fvg_a.top,    fvg_b.top)
zone_bottom = max(fvg_a.bottom, fvg_b.bottom)
```

**Strictly positive overlap required.** `zone_top > zone_bottom`. Two gaps that merely
touch at a single price produce **no** BPR — the same strictness R2-05 applies to gaps
themselves, where exact equality is not a gap. A zero-width BPR is refused at
construction, never stored.

**Adjacency.** The two FVGs must confirm within `max_bars_between` bars of each other
(finite documented default). Unbounded pairing would join gaps months apart and call
the result a structure.

**Direction (proposed default: the later FVG's polarity).** The source describes BPRs
as directional by context, which is not a computable rule; the most recent delivery is
the deterministic proxy. `NEUTRAL` is configurable. **Flagged in the concept map as the
weakest default in this phase** and the one most likely to be revised.

**Lifecycle.** `ACTIVE` → `PARTIALLY_FILLED` → `MITIGATED`, by the same fill arithmetic
as R2-05, measured against the BPR's own zone from its confirmation onward.
Invalidation ≡ full mitigation.

**Cardinality.** One BPR per qualifying **pair**. If three gaps mutually overlap, every
qualifying opposite-polarity pair yields its own BPR with its own id. No merging, no
"best" selection — the same anti-collapse rule as R2-05.9.

## Event schema

```
BalancedPriceRange (frozen)
    bpr_id                  "bpr:<symbol>:<timeframe>:<confirmation ts ISO>:<pair hash>"
    bullish_fvg_id          provenance
    bearish_fvg_id          provenance
    symbol, timeframe, direction
    zone_top, zone_bottom, overlap_points
    event_timestamp         the later FVG's formation timestamp
    confirmation_timestamp  max(both FVGs' confirmation timestamps)
    status                  BprStatus

BprFillUpdate (frozen)      timestamped lifecycle transitions
```

Contract addition: `EventType.BALANCED_PRICE_RANGE`.

## Timestamp semantics

| | |
|---|---|
| `event_timestamp` | the **later** source FVG's formation timestamp |
| `confirmation_timestamp` | `max(fvg_a.confirmation, fvg_b.confirmation)` — the pair is not knowable until both exist |
| invariant | `>=` both sources' confirmations; equality with the later one is expected |

## Leakage acceptance criteria

Inherits L1–L6. Story-specific:

- **L4 (mandatory):** the naive implementation stamping the BPR at the **earlier**
  FVG's confirmation is implemented and proven to publish every BPR too early.
- No BPR is observable before both source FVGs are observable.
- Both source ids resolve within the same analysis.
- Touching-but-not-overlapping gaps produce nothing (adversarial, synthetic).
- Same-polarity overlaps produce nothing.

## Real-data acceptance criteria

EURUSD + XAUUSD on 1m / 5m / 15m / 1H / 4H. Report BPR counts per timeframe and three
real examples with both source FVG ids, the overlap width, and all timestamps. Zero
BPRs on a sparse timeframe is a valid result.

## Batch / streaming criteria

`batch == prefix replay == bar-by-bar`, including the fill stream.

## Known limitations (anticipated)

1. Direction default is a documented proxy, not a rule found in the source (§5.5).
2. `max_bars_between` bounds pairing; distant overlaps are not reported.
3. Pairwise enumeration is O(n²) in overlapping gaps within the window.
4. No cross-timeframe BPR.

## Out of scope

Unicorn, IFVG interaction modelling, ML, signals, scoring.
