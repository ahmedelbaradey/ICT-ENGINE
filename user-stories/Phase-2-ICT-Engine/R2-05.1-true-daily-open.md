# R2-05.1 — True Daily Open (00:00 America/New_York)

- **Project:** ICT-Kronos
- **Phase:** Phase 2 — ICT Engine
- **Epic:** Deterministic ICT representation
- **Issue type:** Story
- **Story points:** 2
- **Labels:** `ict`, `reference-level`, `timezone`, `leakage`
- **Depends on:** R2-01 (timezone/DST machinery)
- **Blocks:** R2-07

## Description

As a quantitative researcher, I want the **True Daily Open** — the opening price of the bar that begins exactly at 00:00 America/New_York — as a deterministic, first-class ICT reference level, so that daily-bias features have a correct, DST-aware anchor that carries no look-ahead bias.

This story is deliberately narrow. The engine gains **one** primitive.

## The definition

```
TRUE_DAILY_OPEN = 00:00 America/New_York = the OPEN price of the bar starting at that instant
```

It is **not** the 17:00 New York trading-day boundary (R2-04, unchanged by this story), not a session open, not the previous day's open or high/low, not the daily high/low/close, not the first bar after a weekend, and not UTC midnight.

## Scope

One immutable record per (symbol, timeframe, NY calendar date) for which an exact boundary bar exists. A new `TRUE_DAILY_OPEN` member on the shared event contract. Nothing else.

## Acceptance criteria

1. The boundary is derived through `zoneinfo` from local `00:00 America/New_York`. **No UTC offset is hardcoded** — `05:00 UTC` / `04:00 UTC` are consequences, never definitions.
2. `price_level` is the boundary bar's **`open`**. `high`, `low` and `close` are never read.
3. `event_timestamp == created_timestamp == confirmation_timestamp ==` the boundary instant. Confirmation does **not** wait for the bar, session, or day to close.
4. **No exact boundary bar ⇒ no record.** No interpolation, no nearest-bar fallback, no previous-close substitute, no carry-forward, no Sunday-reopen substitution.
5. Identity is `(symbol, timeframe, trading_date)` where `trading_date` is the **New York** calendar date. A later date can never mutate an earlier one; records are immutable.
6. Observability goes through the shared gate only. `confirmation_timestamp <=` must not appear in the module, enforced by a source-level test.
7. `TRUE_DAILY_OPEN` exists in the shared `EventType`, without overloading an existing member.
8. R2-01 … R2-05 behaviour is unchanged.
9. **LEAKAGE CRITERION (mandatory):** tests prove the level is not observable before the boundary; that appending future bars cannot modify an existing record; that mutating any later high/low/close/volume leaves every record identical; and that batch equals prefix replay equals bar-by-bar streaming.

## Test coverage required

- One record per valid NY date; price equals the exact source `open`; correct NY local time; correct event type; immutability
- Leakage: nothing before the boundary; observable at it; future bars inert; later OHLC mutation inert; prefix stability
- Timezone: EST period, EDT period, spring transition, autumn transition, local-time invariant (never a fixed UTC hour)
- Weekend / missing data: no synthetic Saturday or Sunday level; no reopen substitution; missing boundary bar yields nothing
- Contract: event type present; shared gate used; no hand-rolled observability comparison
- Replay: batch == prefix == streaming; historical records unchanged after appending
- Real data: EURUSD and XAUUSD on 1m / 5m / 15m / 1h / 4h where the grid permits

## Out of scope

Trading Day Open (17:00 NY), PDH/PDL/PWH/PWL changes, Premium/Discount, dealing range, OTE, entry models, manipulation/expansion legs, CSD, SMT, order/breaker/mitigation blocks, IFVG, BPR, setup scoring, XGBoost/LightGBM, ML training, Kronos, cross-timeframe projection.
