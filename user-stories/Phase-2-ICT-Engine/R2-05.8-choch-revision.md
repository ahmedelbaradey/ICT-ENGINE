# R2-05.8 — CHoCH semantics revision

- **Project:** ICT-Kronos · **Phase:** Phase 2 — ICT Engine · **Issue type:** Story
- **Story points:** 3 · **Labels:** `ict`, `choch`, `structure`, `review`, `regression-risk`
- **Depends on:** R2-03 (structure), R2-05.7 (CISD) · **Blocks:** —
- **Concept map:** [R2-05x-CONCEPT-MAP.md](../../docs/ict/R2-05x-CONCEPT-MAP.md) §5.8

> **This is a review story. It may legitimately end with no behaviour change.** That
> outcome is flagged in advance so it is not later mistaken for dropped scope.

## Objective

Re-evaluate R2-03's default `ChochPolicy.SYNONYM` (CHoCH ≡ MSS) against the ICT
material and against the newly-implemented CISD, and either justify it properly or
change it — with evidence either way. Ensure the architecture **can** represent CHoCH
independently even if the default keeps it as an alias.

## Dependencies

Deliberately scheduled **after** R2-05.7. Deciding what CHoCH means while the only
available "early reversal signal" is CHoCH itself would bias the answer.

## Current state (R2-03, approved)

| Policy | Behaviour |
|---|---|
| `SYNONYM` *(default)* | Counter-trend breaks emit `MSS`; `CHOCH` is never emitted |
| `DISTINCT_BY_DISPLACEMENT` | Counter-trend break emits `MSS` with displacement, else `CHOCH` |

`EventType.CHOCH` already exists, so independent representation is already *possible*;
what is at issue is whether it is *warranted*.

## The evidence

The primary ICT material does **not** define CHoCH as a distinct algorithm. What it
does define is the CISD/MSS relationship: *"CISD is a candle-close signal that prints
early; MSS is a structural break that confirms later"*, and *"MSS is based on wicks
while CISD on closing price."*

**This is the substantive finding.** The role usually invoked to justify separating
CHoCH from MSS — the earlier, weaker reversal hint — is, in the source material,
**CISD's role**. After R2-05.7 that role is filled by a concept with a real definition,
which removes the main practical pressure to split CHoCH from MSS.

## Proposed outcome

1. **Keep `SYNONYM` as the default**, with the justification upgraded from "we found no
   distinction" to "the distinction people reach for is CISD, which now exists."
2. **Add one documented policy** — `DISTINCT_BY_STRUCTURE_SCALE` — for the remaining
   defensible reading in circulation: CHoCH breaks **internal** structure while
   BOS/MSS break **swing** structure. This is deterministic given two swing scales
   (a second `SwingConfig`), and it is the only candidate distinction found that is
   neither a synonym nor a restatement of displacement.
3. **Document the four-way relationship** (BOS / MSS / CHoCH / CISD) in one table in
   `docs/ict/structure.md` so it is not re-litigated.

If (2) proves to require more machinery than it earns, the honest outcome is to
document the reading and **not** implement it. That decision is reported at the
checkpoint with its reasoning.

## Exact semantics under the proposed new policy

```
DISTINCT_BY_STRUCTURE_SCALE
    swing structure     = swings from the primary SwingConfig    → BOS / MSS
    internal structure  = swings from a finer internal SwingConfig → CHOCH
    a counter-trend break of internal structure that is NOT also a break of
    swing structure emits CHOCH; otherwise the existing BOS/MSS labelling applies
```

Confirmation semantics are unchanged: the breaking bar's `close_time`, exactly as for
BOS and MSS.

## Event schema

No new event types. `EventType.CHOCH` already exists. The additions are:

```
ChochPolicy.DISTINCT_BY_STRUCTURE_SCALE     new enum member
StructureConfig.internal_swing_config       SwingConfig | None
StructureBreak.structure_scale              "swing" | "internal"   (new field, defaulted)
```

Every new field is defaulted so existing construction sites are unaffected.

## Timestamp semantics

Unchanged from R2-03. Any change here would be a defect, not a feature.

## Leakage acceptance criteria

- Existing R2-03 leakage tests continue to pass **unmodified**.
- Under the new policy, internal-structure breaks obey the same confirmation rule;
  a CHoCH is never observable before its breaking bar closes.
- Internal swings carry their own confirmation lag and a CHoCH inherits it —
  `confirmation_timestamp >= internal_swing.confirmation_timestamp`.

## Regression acceptance criteria (the real risk in this story)

- **Under `SYNONYM`, output is byte-identical to the pre-change detector** on real
  EURUSD and XAUUSD across every validated timeframe. This is asserted directly, not
  argued.
- BOS and MSS counts, timestamps and labels are unchanged under every pre-existing
  configuration.
- No existing test is modified to accommodate the change. If one must be, that is
  reported at the checkpoint as a behaviour change requiring explicit approval.

## Real-data acceptance criteria

EURUSD + XAUUSD on 1m / 5m / 15m / 1H / 4H. Report, per timeframe: BOS/MSS counts under
`SYNONYM` before and after (must match exactly), CHoCH counts under the new policy if
implemented, and a comparison of CHoCH against CISD on the same bars.

## Batch / streaming criteria

Unchanged from R2-03 and re-verified.

## Known limitations (anticipated)

1. `DISTINCT_BY_STRUCTURE_SCALE` requires choosing an internal swing scale — another
   configured interpretation, which is why it is not default.
2. The ICT material does not settle CHoCH; this story documents a choice, not a
   discovery.
3. Any distinction remains sensitive to swing parameters.

## Out of scope

New detectors, BOS/MSS redefinition, ML, signals.
