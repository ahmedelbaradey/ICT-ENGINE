# R2-05.4 — Breaker Block

- **Project:** ICT-Kronos · **Phase:** Phase 2 — ICT Engine · **Issue type:** Story
- **Story points:** 5 · **Labels:** `ict`, `breaker`, `composite`, `leakage`
- **Depends on:** R2-05.3 (Order Block), R2-03 (structure) · **Blocks:** R2-05.9
- **Concept map:** [R2-05x-CONCEPT-MAP.md](../../docs/ict/R2-05x-CONCEPT-MAP.md) §5.4

## Objective

Implement the Breaker Block as a **failed Order Block**, never as an independent candle
pattern. `BreakerDetector` consumes `OrderBlockDetector` output.

## Dependencies

```
Order Block (R2-05.3)
      ↓ invalidation — a close beyond the far edge against the OB's direction
   failed OB
      ↓ (optionally) a confirmed structure break / liquidity event
Breaker Block
```

## Exact semantics

**Failure.** An Order Block fails when a bar **closes** beyond the far edge of its zone
against the OB's direction — the primary source's test: *"If price closed past the OB
extreme, the OB has failed — that is a Breaker Block, not a Mitigation."* A wick beyond
the edge is not a failure. This is exactly R2-05.3's `INVALIDATED` transition, consumed
rather than recomputed.

**Polarity flips.** A failed **bullish** OB becomes a **bearish** Breaker and vice
versa — the level that failed as support is expected to act as resistance.

**Zone.** Inherited unchanged from the source Order Block, including whichever
`FULL_RANGE` / `BODY` convention that OB was built with. The Breaker does not re-derive
geometry.

**Confirmation (proposed default).** The close_time of the bar whose close failed the
OB. With `require_structure_break=True`, confirmation is deferred to the close_time of
the first confirmed R2-03 break in the Breaker's direction at or after the failure —
strictly later, and recorded as provenance.

**Retest is not confirmation.** The source describes trading a breaker on its retest;
a retest is a **lifecycle event** on an already-confirmed Breaker, recorded in the
update stream, never a precondition for the Breaker existing. Conflating the two would
make the event unobservable until an arbitrary later moment.

**Mitigation / invalidation.** Mitigation = price trades back into the zone (fill
percentage, as elsewhere). Invalidation = a close beyond the far edge *against the
breaker's new direction* — i.e. the Breaker itself fails. Terminal; no re-flip.

**Mitigation Block is explicitly not implemented** in this phase (concept map §5.4). It
is the complement of a Breaker — same level, OB held instead of failing — and its
absence is a recorded decision.

## Event schema

```
BreakerBlock (frozen)
    breaker_id              "breaker:<symbol>:<timeframe>:<failure ts ISO>"
    source_order_block_id   provenance — resolves in the same analysis
    symbol, timeframe
    original_direction      the source OB's polarity
    direction               the flipped polarity
    zone_top, zone_bottom   inherited from the source OB
    failure_timestamp       the failing bar's open
    event_timestamp         == failure_timestamp
    confirmation_timestamp  the failing bar's close_time (or the structure break's)
    source_break_id         str | None   provenance when require_structure_break
    source_sweep_id         str | None   provenance, optional
    status                  BreakerStatus

BreakerUpdate (frozen)      retest / fill / invalidation, timestamped
```

Contract additions: `EventType.BREAKER_BULLISH`, `EventType.BREAKER_BEARISH`.

## Timestamp semantics

| | |
|---|---|
| `event_timestamp` | the failing bar's open |
| `confirmation_timestamp` | that bar's close_time — failure is a *close* test |
| invariant | `>= source_order_block.confirmation_timestamp`, strictly later |

## Leakage acceptance criteria

Inherits L1–L6. Story-specific:

- **L4 (mandatory):** the naive detector that flips polarity on the **wick** piercing
  the OB is implemented and proven to fire earlier and more often.
- No Breaker is observable before its source OB is observable — a Breaker whose OB is
  still unconfirmed is a contradiction and must be impossible to construct.
- A retest cannot alter the confirmed record.
- No Breaker is produced from an OB that was merely mitigated (touched) rather than
  closed through.

## Real-data acceptance criteria

EURUSD + XAUUSD on 1m / 5m / 15m / 1H / 4H. Report Breaker counts, the OB→Breaker
conversion rate, and three real examples with source OB id and both timestamps.

## Batch / streaming criteria

`batch == prefix replay == bar-by-bar`, including the update stream.

## Known limitations (anticipated)

1. Reading A (failed OB) is implemented; the classic swing-construction reading is
   documented and not implemented (concept map §5.4).
2. Breaker inherits every limitation of the OB qualifier it was built from.
3. No Mitigation Block, no Rejection Block.

## Out of scope

Unicorn (R2-05.9), Mitigation Block, ML, signals, scoring.
