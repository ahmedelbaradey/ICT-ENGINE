- **Project:** ICT-Kronos · **Phase:** Phase 2 — ICT Engine · **Issue type:** Story

## Objective

Deterministic Order Block detection with an explicit, configurable **qualifying
condition**. The story exists to avoid the insufficient definition *"the last opposite
candle before a move"* — which labels an OB on nearly every reversal candle and cannot
be confirmed at a well-defined instant.

**`docs/ict/order_blocks.md` is written before any implementation.**

## Exact semantics

**Candle pattern.** A **bullish OB** is the last **down-close** candle immediately
preceding an up-impulse that **engulfs** it — the next bar closes above the OB
candle's high. Bearish is the mirror. `require_engulf` is configurable; default on.

**Qualifying condition (proposed default Q3).** The candle pattern alone does not make
an Order Block. The OB is qualified when, within `displacement_window` bars of the OB
candle:

1. a bar shows **displacement** — `range / mean(range of previous N bars) >= factor`,
   the identical definition already used in R2-03 and R2-05, **and**
2. an **FVG confirmed by `FvgDetector`** exists inside the impulse leg.

Options: `require_fvg=False` demotes to Q2 (engulf + displacement);
`require_structure_break=True` promotes to Q4 (adds a confirmed R2-03 break). Every
option is documented with its trade-off; none is chosen silently.

**Zone boundaries (proposed default `FULL_RANGE`).** The OB candle's `high`–`low`.
`BODY` (open–close) is configurable. `mean_threshold` (the 50% level) is exposed as a
property, never re-derived downstream. Rationale for the default: the wider zone is
touched sooner, so it mitigates sooner, so the detector errs toward declaring an OB
*spent* rather than still live.

**Mitigation** — price trades back into the zone; tracked as a fill percentage exactly
as R2-05 tracks FVG fill, with the same configurable thresholds.

**Invalidation** — a bar **closes** beyond the far edge of the zone against the OB's
direction. Invalidation is a distinct terminal state from mitigation and is **the
precondition for R2-05.4**; the failure timestamp is recorded because the Breaker story
consumes it.

## Event schema

```
OrderBlock (frozen)
    order_block_id          "ob:<symbol>:<timeframe>:<ob candle ts ISO>"
    symbol, timeframe, direction
    zone_top, zone_bottom, mean_threshold
    ob_candle_timestamp     the source candle's open
    event_timestamp         the OB candle's open (chart location)
    confirmation_timestamp  close_time of the bar completing the qualifier
    displacement_ratio      float
    source_fvg_id           str | None      provenance (Q3/Q4)
    source_break_id         str | None      provenance (Q4)
    source_sweep_id         str | None      provenance, optional
    status                  OrderBlockStatus

OrderBlockUpdate (frozen)   lifecycle transitions, timestamped
```

Contract additions: `EventType.ORDER_BLOCK_BULLISH`, `EventType.ORDER_BLOCK_BEARISH`.

## Timestamp semantics

| | |
|---|---|
| `event_timestamp` | the OB **candle's** open — where it sits on the chart |
| `confirmation_timestamp` | close_time of the bar that completes the qualifier — typically **several bars later** |
| invariant | `confirmation_timestamp` > `event_timestamp`, and >= every source event's confirmation |

**This gap is the whole point of the story.** An Order Block is not knowable when its
candle closes; it becomes knowable only once the move that qualifies it exists. The
naive implementation that stamps it at its own candle is L4.

## Leakage acceptance criteria

Inherits L1–L6. Story-specific:

- **L4 (mandatory):** the naive detector stamping the OB at its own candle's close is
  implemented in tests and proven to publish every OB earlier than the causal one.
- No OB is observable before its qualifying event confirms.
- Every `source_fvg_id` / `source_break_id` resolves and is observable no later than
  the OB.
- Mutating bars after qualification cannot change the zone, direction or timestamps.
- The detector must not re-implement FVG, swing or structure detection — enforced by a
  source-level import guard.

## Real-data acceptance criteria

EURUSD + XAUUSD on 1m / 5m / 15m / 1H / 4H. Report OB counts per timeframe, the
distribution of confirmation lag in bars (expected: **> 1 bar**, unlike every prior
detector), and at least three real examples with full provenance.

## Batch / streaming criteria

`batch == prefix replay == bar-by-bar`, including the mitigation stream.

## Known limitations (anticipated)

1. The qualifier is a **choice**, documented in concept map §5.3; other defensible
   choices produce different OB populations. This is disclosed, not hidden.
2. `displacement_window` bounds how far the qualifier may look; OBs qualified later
   than the window are not emitted.
3. No "hidden", "propulsion" or "rejection" OB variants.
4. No ranking or quality score — deferred with the rest of setup scoring.

## Out of scope

Breaker (R2-05.4), Mitigation Block (not in this phase), ML, signals, scoring.
