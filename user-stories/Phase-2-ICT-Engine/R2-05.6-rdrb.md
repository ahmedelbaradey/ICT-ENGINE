## Objective

Implement the Redelivered Rebalanced Price Range as a deterministic delivery pattern
that is **not** an FVG, **not** a BPR, and **not** a generic two-candle pattern.

**`docs/ict/rdrb.md` is written before any implementation**, and must open by stating
which reading was adopted and why.

## Decision required before implementation

| | Reading A — primary source (`innercircletrader.net`) | Reading B — wider community |
|---|---|---|
| Candles | **two**: deliver → retrace leaving a wick → redeliver | **three** with containment rules |
| Zone | *"the area between these two wicks"* — the wicks of the candles **surrounding** the pair; *"Forget the RDRB pair itself"* | between the pattern candles themselves |
| Character | a *hidden* range inside apparently efficient delivery | a visible imbalance, FVG-shaped |

**Proposed: Reading A.** The brief names that site as the reference, and Reading B is
close enough to a Fair Value Gap that R2-05 would largely subsume it — producing a
detector whose output correlates with an existing one, which the brief explicitly warns
against. Reading B will be documented as the alternative not adopted.

Only one reading is implemented. No competing implementations.

## Exact semantics (under Reading A)

**Bullish RDRB — the pair.** Candle `P1` closes up and leaves an **upper wick**
(`high > close`, retraced before the close). Candle `P2` opens and closes up,
continuing the delivery (`close(P2) > close(P1)`). Bearish is the mirror: `P1` closes
down leaving a **lower wick**, `P2` closes down and lower.

Minimum wick size is configurable (`min_wick_points`, and/or a fraction of the candle's
range) so that a floating-point wick does not qualify. Contiguity in time is required
between `P1` and `P2` — the R2-05 guard, for the same reason.

**The zone is drawn from the surrounding candles, not the pair.** Let `B` be the candle
immediately **before** `P1` and `A` the candle immediately **after** `P2`. For the
bullish case the zone spans the wick prices of `B` and `A` on the delivery side; the
exact price pair will be fixed in `docs/ict/rdrb.md` with a worked example, because the
source's phrasing is loose and must not be guessed at in code.

**Consequence — and it is the leakage crux of this story:** because the zone requires
candle `A`, an RDRB is **not knowable when `P2` closes**. Confirmation is `A`'s
`close_time`. Any implementation stamping it at `P2` is the naive one.

**Zero-width and degenerate zones** are refused at construction, never stored.

**Lifecycle.** `ACTIVE` → `PARTIALLY_FILLED` → `MITIGATED` on re-entry into the zone,
by the same fill arithmetic used elsewhere.

## Event schema

```
RdrbZone (frozen)
    rdrb_id                 "rdrb:<symbol>:<timeframe>:<A ts ISO>"
    symbol, timeframe, direction
    zone_top, zone_bottom
    before_candle_timestamp     B   provenance (source candles)
    first_candle_timestamp      P1
    second_candle_timestamp     P2
    after_candle_timestamp      A
    event_timestamp         P1's open — where the pattern begins on the chart
    confirmation_timestamp  A's close_time — when the zone became drawable
    wick_points             the rebalancing wick's size
    status                  RdrbStatus

RdrbFillUpdate (frozen)     timestamped lifecycle transitions
```

Contract additions: `EventType.RDRB_BULLISH`, `EventType.RDRB_BEARISH`.

## Timestamp semantics

| | |
|---|---|
| `event_timestamp` | `P1`'s open |
| `confirmation_timestamp` | `A`'s **close_time** — three bars later than `P1`'s open |
| invariant | `confirmation_timestamp` > `event_timestamp` by a documented, fixed number of bar durations when the bars are contiguous |

## Leakage acceptance criteria

Inherits L1–L6. Story-specific:

- **L4 (mandatory):** the naive implementation that stamps the RDRB at `P2`'s close —
  using `A`'s wick to draw a zone it dates before `A` existed — is implemented and
  proven to publish every zone one bar early.
- Mutating `A` changes the zone (control); mutating anything after `A` does not.
- No RDRB spans a weekend or data gap (contiguity guard, R2-05 precedent).
- Prefix replay never yields an RDRB whose `A` has not yet closed.

## Real-data acceptance criteria

EURUSD + XAUUSD on 1m / 5m / 15m / 1H / 4H. Report counts per timeframe, both bullish
and bearish examples with all four source-candle timestamps, and an explicit comparison
against `FvgDetector` output on the same bars showing that RDRB is **not** simply
re-detecting FVGs — a low overlap rate is the evidence that Reading A was worth
implementing.

## Batch / streaming criteria

`batch == prefix replay == bar-by-bar`, including the fill stream.

## Known limitations (anticipated)

1. Reading A is adopted from a single primary source whose zone phrasing is loose; the
   precise price pair is a documented interpretation, not a quotation.
2. Reading B is not implemented.
3. Wick-size thresholds are configuration; results are sensitive to them and this must
   be reported, not smoothed over.
4. The confirmation requires a trailing candle, so the last pattern in any window is
   necessarily unconfirmed and not emitted.

## Out of scope

FVG re-detection, BPR, ML, signals, scoring.
