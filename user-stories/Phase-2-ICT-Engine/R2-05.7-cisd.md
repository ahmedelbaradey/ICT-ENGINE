# R2-05.7 — Change In State of Delivery (CISD)

- **Project:** ICT-Kronos · **Phase:** Phase 2 — ICT Engine · **Issue type:** Story
- **Story points:** 5 · **Labels:** `ict`, `cisd`, `delivery`, `leakage`
- **Depends on:** — (bars only; R2-04 optional) · **Blocks:** R2-05.8 (CHoCH review)
- **Concept map:** [R2-05x-CONCEPT-MAP.md](../../docs/ict/R2-05x-CONCEPT-MAP.md) §5.7

## Objective

Implement Change In State of Delivery as an **independent delivery-state concept**,
deliberately not derived from `StructureDetector`. The engine must be able to hold
`CISD`, `BOS`, `MSS` and `CHoCH` as four separate events.

## Dependencies

```
bars ──► consecutive same-direction delivery run ──► body close through the run's open ──► CISD
```

`LiquidityDetector` is consumed **only** when `require_prior_sweep=True`, which is off
by default. `StructureDetector` is **not** consumed — a source-level guard enforces it.

## Exact semantics

**The rule, from the primary source.** *"A bullish ICT change in the state of delivery
prints when price closes above the opening price of a bearish delivery leg"*; bearish
is the mirror. And, decisively: *"ignore the wicks. Only the opening and closing prices
matter."*

**Delivery run.** A maximal sequence of **consecutive** candles closing in the same
direction (down-close candles for a bearish run). Contiguity in time is required —
runs are not stitched across weekends or data gaps.

**Trigger level (proposed default `SERIES_OPEN`).** The **open of the first candle in
the run** — the price at which that delivery series opened. Source wording: *"the
opening price of the final consecutive series of those down-closing candles."*

The alternative `EXTREME_OPEN` (the highest open in a bearish run) is configurable but
not default: it can only be found by scanning the whole run, which invites exactly the
hindsight framing the leakage tests exist to catch.

**The transition.** A bullish CISD fires when a candle's **close** exceeds the bearish
run's trigger level. Bodies only — a wick above the level is explicitly not a CISD.

**Confirmation.** The close_time of the candle whose close crosses the level. One bar
of lag, always.

**Optional prior sweep.** `require_prior_sweep=True` requires a confirmed R2-04 sweep
within `sweep_window` bars before the transition, recorded as provenance. Off by
default — the source is explicit that *"CISD alone is just a candle close."*

**Invalidation.** A subsequent CISD in the opposite direction supersedes the delivery
state. The prior CISD record is **never mutated**; state is a separate query
(`delivery_state_at(t)`), the R2-03 pattern.

**CISD is not MSS.** Recorded in the schema and in the docs: CISD reads **opens and
closes**; MSS reads **swing levels**. Per the source, *"CISD is a candle-close signal
that prints early; MSS is a structural break that confirms later."* Both may fire on
the same bar; neither implies the other; a test asserts they are independently derivable
and can disagree on real data.

## Event schema

```
Cisd (frozen)
    cisd_id                 "cisd:<symbol>:<timeframe>:<trigger bar ts ISO>"
    symbol, timeframe, direction
    trigger_level           the delivery run's open
    trigger_close           the close that crossed it
    run_start_timestamp     first candle of the delivery run
    run_end_timestamp       last candle of the delivery run
    run_length              int
    event_timestamp         the crossing bar's open
    confirmation_timestamp  the crossing bar's close_time
    source_sweep_id         str | None    provenance when require_prior_sweep
    previous_state          DeliveryState
    resulting_state         DeliveryState

DeliveryState               BULLISH | BEARISH | UNDEFINED
```

Contract additions: `EventType.CISD_BULLISH`, `EventType.CISD_BEARISH`.

## Timestamp semantics

| | |
|---|---|
| `event_timestamp` | the crossing bar's open |
| `confirmation_timestamp` | that bar's close_time — the rule reads a close |
| invariant | exactly one bar duration of lag on contiguous bars |

## Leakage acceptance criteria

Inherits L1–L6. Story-specific:

- **L4 (mandatory):** the naive implementation anchoring to the run's `EXTREME_OPEN`
  as discovered with hindsight, and/or triggering on a **wick** through the level, is
  implemented and proven to fire earlier and more often than the causal one.
- A wick above the trigger level with a close below it produces **no** CISD.
- The delivery run is computed only from candles at or before the trigger bar; a later
  candle extending the run cannot retro-change an already-published CISD.
- `delivery_state_at(t)` never reflects a CISD confirmed after `t`.
- Source-level guard: `cisd.py` does not import `structure.py`.

## Real-data acceptance criteria

EURUSD + XAUUSD on 1m / 5m / 15m / 1H / 4H. Report CISD counts per timeframe, three
real examples with the run, the trigger level and both timestamps, and — required — a
**comparison table against R2-03 MSS on the same bars** showing where the two agree and
where they diverge. Divergence is the evidence that CISD is a separate concept.

## Batch / streaming criteria

`batch == prefix replay == bar-by-bar`, including delivery-state transitions.

## Known limitations (anticipated)

1. `SERIES_OPEN` is a documented interpretation of loose source wording (§5.7).
2. No higher-timeframe delivery context; timeframe-local only.
3. Single-candle runs are legal by definition and may produce frequent CISDs on noisy
   timeframes; counts must be reported, not filtered to look tidy.
4. No holiday/session awareness beyond the contiguity guard.

## Out of scope

Structure changes (that is R2-05.8), ML, signals, scoring, entries.
